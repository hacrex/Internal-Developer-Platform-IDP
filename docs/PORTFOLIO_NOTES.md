# Portfolio Notes

## My focus

I use this project to explain platform engineering in practical terms: a developer should have a supported path to create a service, understand who owns it, find its operational information, and request infrastructure without giving a UI direct cloud credentials.

## Evidence I can show

- `app-config.yaml` for platform configuration and integration boundaries.
- `catalog-info.yaml` for service/catalog metadata.
- `demo-template/` for scaffolding concepts.
- `docs/DEPLOYMENT_GUIDE.md` for local and production prerequisites.

## Known boundary

This repository is not a deployed internal company portal. It is an upstream-based evaluation environment with portfolio-specific positioning and documentation.
